卫戍协议助手 Windows 0.1.14 · 开发预览版

启动
解压整个文件夹，双击“卫戍协议助手.exe”。请保留旁边的 _internal 文件夹。
目标环境 Windows 10 22H2 / Windows 11 64 位；已打包 Python、Qt、离线 OCR 模型及三份资料/图片数据库，无需另装 Python。
当前已在本机完成便携包检查，其他电脑与 Windows 版本尚未测试。
首次加载识别模型会比后续识别慢。程序仅截取所选游戏窗口，提供资料与建议，不向游戏发送操作。

资料图鉴
左侧保留四列干员与核心 / 副盟约 / 作用 / 等阶按钮筛选。右侧分“概览、特质、技能、资料”四页，点击页签切换。
“普通 / 精锐”按钮同步切换特质、效果上限、培养规格与技能 4 / 7 级数据；不会修改本局阵容的晋升状态。切换干员保留当前页与普通 / 精锐选择。
概览显示立绘、等阶、招募资金、盟约图标和技能选择建议；技能页用 S1 / S2 / S3 按钮选择技能，并单独展示初始技力、消耗技力与持续时间。
资料页保留原型替代、常规参考、条目说明和可点击来源。缺少数据时不补造数值。

窗口
主窗口右上角“—”最小化到任务栏；“×”收起到系统托盘。完全退出可在托盘菜单或“数据与设置”中操作。
悬浮面板“−”收起后保留置顶的小图标；图标可拖动，单击恢复悬浮面板，双击打开主窗口。
主窗口“悬浮终端 · 开/关”按钮切换开启/关闭；关闭时面板与悬浮图标一起关闭，不退出主程序。悬浮面板内不再放关闭按钮，保留回主窗口与最小化。快捷键仍用于最小化/恢复。
悬浮面板顶部固定“已追踪”，下面先展示当前分析和操作建议、可点选推荐名单，再展示目标盟约与补位方向；AI 已开启且结果仍适用时优先显示 AI 建议，否则显示本地建议。识别耗时、置信度、区域与原文保留在主窗口“画面识别”，不进入悬浮建议。
AI 普通分析也会说明操作顺序、原因、收益、条件、资金安排、备选与后续目标；“深入分析”进一步比较路线和装备。调用量与费用可在自定义 API 设置页查看。
AI 输入包含本局禁选核心、附加盟约、推算禁用与待确认干员及过滤后的目标候选。目标返回后再核对；购买按当前资金和禁选顺序验证。缺少禁选信息时会提示先确认，不把空名单视作全员可用。换组或修改禁选后，旧建议收起并重新分析。
应用与悬浮入口使用新的绿色全息表情图标。默认 56 像素，可在设置调整为 40—80 像素。
资料图鉴左侧固定每行四个干员；头像卡片填满格子，紧密排列。拖动分隔条调整左右宽度。
图鉴按核心盟约、副盟约、干员作用分组点按按钮筛选，同组多选满足任一项，不同组与搜索词共同限制结果；再次点按取消。等阶单选；每组“全部”清除此组，“重置筛选”清除所有条件和搜索词。结果数量实时显示，按钮随窗口宽度换行。
费用徽章与选中边框分层绘制，徽章两侧留出间隔，避免选中线压住费用。
首页采用原版默认终端的状态轨道、切角阶段牌、环形盟约容器和底部调度卡槽；小窗口可滚动查看完整内容。

攻略推荐来源与删除
未开启 AI 时采用已总结的本地攻略库：11 条路线、20 项署名来源（19 个视频及11张图文）。按策略、已有成员、当前商店、目标盟约及本局禁选匹配；没有合适路线时退回机制参考并说明缺失条件，不把机制评分冒充作者攻略。
开启 AI 后，将已上传的 garrison-strategy-guide 技能原文，以及与本局相关的最多3份路线正文、机制辅助和作者来源，随当前局面发送给所配置的 Chat Completions 接口。使用本地随包技能快照，不要求服务商原生支持“技能”接口，也不通过名称假装远程调用。测试连接不会发送攻略或对局信息。
技能快照对应已上传仓库 Nijuu-20/garrison-strategy-guide，2026-11-13 版本，提交 984867666227eeabcb12e41ac06936f967c5513e。资料均随便携版打包；运行时不联网下载攻略。
本地建议、AI 建议下方保留对应作者与原链接；未标明采用出处的模型结果只标为本次提供的参考资料，不冒称模型已经引用。不同作者变体分别保留，不把中后期展示补写成完整开局。来源整理未做游戏复现，匹配排序是助手的局面推断，不代表作者排名或实测胜率。
核心、过渡和可选终端的名单可点选追踪；常规招募、晋升奖励与后续升本区分说明。转职必须同时满足组件条件。缺少策略或关键盟约被禁时，不硬套依赖它们的路线。
“阵容攻略库”显示整理好的原文与可点击来源，自建记录另行保留。“删除攻略线路”确认后移除所选线路；内置线路同步退出本地和 AI 推荐范围，已上传的原始攻略文件保留。删除自建攻略会连同其附带阵容记录移除，不改变当前对局或已追踪名单。
“自定义 API 配置”新增“删除配置”。确认后停止当前请求，移除所选配置及其本机加密密钥，清空当前选择并关闭 AI；其他配置保留。重新选择其他配置后可再启用 AI。删除前点取消不会改变任何配置。

阵容 / 装备追踪
AI 返回独立的阵容 / 装备推荐名单，在建议正文下方显示为选项，不将名单拼进正文。点击候选加入追踪；再次点击顶部已追踪项即可取消。推荐理由可悬停查看。
主窗口 AI 回合教练与悬浮面板同步，顶部已追踪项不随建议正文滚动。刷新 AI、关闭 AI、新对局或重启不会自动清掉你明确选择的追踪项；新对局建议与旧商店框选会清除。
点击“手动选择”，可搜索干员、盟约或装备并勾选追踪，不依赖 AI。当前禁用干员会标注“本局禁用”，不会作为 AI 推荐候选或商店高亮目标。
在“画面识别”选择游戏窗口、开始实时识别，同时开启悬浮终端。商店中连续确认出现追踪项后，在对应商品外画金色框；干员、装备和购买格位按本帧重新定位，不假定升级前后位置不变。
框选只提示，不拦截鼠标或键盘，不自动点击购买。无需打开“自动更新局面”也能框选。最小化为悬浮图标后仍可提示；主窗口关闭悬浮终端时高亮层一起关闭。
切换到其他应用、游戏最小化、尺寸变化、商品变动、识别不确定或暂停实时识别时撤下旧框。实时框选另外检查最新画面的静态商品名称区，避免旧识别结果盖在刷新后的商品上。
导入截图时仅在识别预览显示框选；手动布局只对明确标注的商店干员区域框选，不推断整张商品卡。自动定位支持商店干员与装备。
当前已用保存的 1、5、6 级商店截图、离屏控件与模拟窗口几何检查；实际游戏置顶层、混合 DPI 多屏与动态光效仍需授权后的实机验收。无法获得持续的新鲜窗口帧时暂不叠加高亮。

Ctrl+Shift+F11：悬浮面板最小化 / 恢复
Ctrl+Shift+F9：截取所选窗口并识别

开局禁选与单人建议
单人实时识别保留最近一次完整信息，短暂漏图不再使面板反复清空；出现不同选组或禁选时，暂停旧建议并在完整结果重复一致后替换。漏读期间明确显示待核对，不能确认保留的旧画面；不会用旧图标补齐新结果。
低难度支持核心全部启用、附加盟约禁用少量或全部启用，不再要求各禁用 5 个。确认的依据是完整读到 10 个核心与 16 个附加盟约的亮暗状态；“没有读到图标”不等于“没有禁选”。核心全启用时不要求左右选择。
开局识别失败后，可在游戏内打开“本局信息”，再点击悬浮终端底部的“核对本局禁选”（主窗口也有“局内重新核对禁选”）。这会按图标重新读取当前禁选，然后在悬浮终端点击“确认本局禁选”；已有实时识别时可沿用稳定后自动确认。图标未展示完整时保持待核对，可点击“重新读取禁选”重试，或“返回局面”取消核对。
局内核对保留原对局、回合、资金、阵容、装备与商店，只替换本局禁选并刷新本地 / AI 约束。无需重新建立对局，也不会替玩家点击游戏界面。
反复更改左右选组时，以最新完整候选核验。一帧与该候选一致的漏读不会清空新候选计数；出现相反图标或连续漏读仍等待重新核验。
核验按盟约身份与亮暗状态比较，不受识别列表顺序变化影响。完整结果之间可容忍一次不冲突的短暂漏读；多帧漏读或超过核验时间则重新计数。稳定读到整备 / 作战界面后收起开局面板，已确认禁选仍保留到本局结束。
在“确认本局信息”画面，使用“画面识别”截取、导入或粘贴游戏截图。程序先按盟约图标识别，不使用开局文字或禁用干员头像比对。
识别到开局后自动显示“开局禁选”页：单人按图标分成左右两组，并读取当前高亮下划线；联机显示固定配置，不提供左右选择。
根据玩家实测修正禁用推算：有主核心的干员按主核心判断，附加盟约禁选不额外排除。例如乌萨斯可用、突袭被禁时，赫拉格仍可获取。只有无主核心的干员，才在全部附加盟约被禁时排除。保留本地网页的主核心归属映射；独行不参与禁选。网页未收录的“盟约·辅助干员”“暴躁铁皮”按现有附加盟约计算。
单人左右分别计算可用池，依据目标盟约、低阶成型费用、叠层能力推荐起步路线；不是胜率排序，也未评估领袖克制。建议只显示在助手中，不替你点击游戏。
“稳定识别后自动确认开局禁选”默认开启：启动实时识别后，完整图标、亮暗和单人实际选组连续多帧一致即自动确认，独立于“连续稳定后自动更新局面”。确认后立即更新本地推荐和 AI 禁用约束；不会替你操作游戏选组或准备就绪。
也可在悬浮终端的“本局禁选”卡片核对禁选核心与附加盟约，一键“确认本局禁选”；自动确认开关与主窗口同步。单次截图需手动确认；图标不全或单人选组未确定时不能确认。重复识别同一结果不会重复写入对局记录。
图标缺失、遮挡或高亮未确定时，不自动猜补；可双击盟约行核对状态，单人用“核对当前选组”记录实际选择，再确认。切换游戏中的组后应重新识别；旧禁用名单会被替换，而不是累加。
新对局清除上局禁选；导出的通用阵容不携带本局限制。AI 自定义 API 与独立开关保持原样，开局推荐离线计算，不调用 API。
盟约身份模板来自本地 PRTS 盟约图标数据库，包含 10 个核心和 16 个附加盟约的透明原始 PNG，保留原图校验值与来源。运行时匹配透明轮廓，不使用旧截图盟约模板；截图只提供 4 个版面定位锚点。原数据库不作修改，也无需联网下载。
验证使用两张历史 16:9 官方 PC 端开局截图及缩放、亮度、遮挡等合成变化；不是新的游戏实机测试。其他主题、窗口比例与实际动态切组仍需实机验收。

快速开始
1. “编队工坊”拖拽干员到战场/整备区，或双击资料池添加。每个同名实例独立保存精锐、技能、装备。
2. 选择目标盟约，在“策略与资金”录入资金、回合、等级、升级/刷新费用及商店实际价格。
3. “作战终端”立即显示本地推荐；“盟约与层数”查看生效门槛、明确公式和补位干员。
4. “装备仓库”录入库存、查看组合配方；回到编队工坊给所选实例分配。两件同名基础装备自动进阶，消耗品不能作为常驻装备。
5. 保存阵容后可以导出 JSON 或 PNG 分享图。分享文件不含 API 配置、密钥或截图。

官方 PC 端识别
使用 Windows Graphics Capture 直接读取所选游戏窗口；兼容路径为传统窗口截取，不会退回截取整个桌面。
1. 游戏使用窗口化或无边框窗口，整备时展开商店。在“画面识别”选择官方 PC 游戏窗口。
2. 使用“官方 PC · 自动定位”，点击“开始实时识别”。无需先手动拖框，预览会显示本帧定位区域。
   每帧重新定位调度等级面板、商品名称与费用标记。商店扩展、装备/干员移位时不沿用上一帧的格子。
   调度等级读取 LEVEL 下方的阿拉伯或罗马数字；不会把顶部“规程等级”当作调度等级。
   商店商品全部对应、连续稳定后整体更新；装备商品单独显示，不进入已拥有库存。
3. 若需要补充其他文字，可拖框建立手动布局并另存。手动框只按分辨率缩放，不随等级或商店变化移动。
   每个干员名称和价格单独标注，同一商品使用相同槽位编号。“头像”仅适用于完整方形头像，不能用于战场小人。
4. 在“识别结果与校正”检查原文、置信分数与结果。可修正单个字段或确认当前可用结果。
5. 开启“实时识别”，并单独打开“连续稳定后自动更新局面”才会自动写入。
   默认间隔 1.5 秒、最低分数 0.92、连续两帧一致，单个任务未完成时不会堆积新任务。

识别边界
置信度是模型/形状分数，不是实测准确率。0.1.3 使用实际可露希尔主题 1、5、6 级 PC 画面，分别验证回合、资金、等级及商店等 14、18、17 个可见字段；1920/1280 检查为这三张画面的缩放副本。
满级通过“已满级”标记读取等级 6，清除上一等级的升级费用；商店数量不从等级推测，仍按实际商品逐个对应。
当前采用界面标记和费用徽章动态定位；不同主题、其他局面、特效遮挡及模拟器仍需更多实战样本。战场小人不会仅凭商店头像数据库猜测身份。
0.1.6 新增“战场小人比对”独立开关，使用新建的 143 人 / 282 正背面模型库及待机动作索引，已随便携版打包，完全离线。
仅在整备阶段且可定位展开商店时自动比对。默认战场脚底范围为画面中部偏左，整备脚底范围随商店上沿移动；其他地图可在预览拖框，选择“战场比对范围”或“整备比对范围”，然后另存布局。这两类范围不会关闭自动商店定位。
名称框显示模型比对结果，黄色表示待确认。默认连续两帧稳定后更新实例，未识别位置不等于空位。当前实测第 14 回合两帧分别得到 8 / 7 个可用结果（9 个可见干员），机械师及光效遮挡仍有漏检；未验证战斗动画、其他皮肤与全部地图。
同名小人按位置分开记录；移动时尽量延续同一实例的装备和精锐状态。被遮挡或离场的旧实例显示“暂不可见”，不继续计入推荐；可核对后手动移除，或选中后“改为手动维护”。已有同名手动干员时不自动添加可能重复的实例。
新识别实例不猜测精锐状态，选择干员后用“确认所选精锐状态”确认。比对结果可能不完整，补齐遗漏后点击编队工坊“已核对当前完整阵容”；阵容或回合变化会重新要求核对，自动 AI 教练在核对前暂停。手动 AI 分析会收到局部阵容与未知状态提示。
商店余额不足时银色价格也会定位。当前规则库未唯一收录 Stormeye 本体，因此遇到这一名称会显示待确认，不按多个干员共用的原型名称猜测商品。
精锐文字可以识别；仅有图形的精锐标记、装备图标和空槽没有对应游戏样本模板，需人工维护。
手动标注的库存装备名称先进入待确认区，确认后替换库存；自动识别的商店装备始终作为未购买商品保存。
未知/被遮挡的信息不会猜测为空；出售或换位后必须核对旧实例，必要时手动移除或调整。
若资金或商店识别不确定，相关购买建议不通过执行条件校验；AI 自动分析会暂停等待可靠字段。
游戏最小化或截取黑屏会暂停当前识别；恢复窗口后重试。独占全屏与部分显卡渲染模式可能无法截取。
“新对局”会归档上一局并清空状态。稳定识别到回合从较大值重新变为 1 且处于整备时，也会归档清空。
手动确认过的回合字段会锁定；如需再次交给自动识别，点击“解锁全部手动字段”。
遇到误识别，可在画面识别页点击“导出识别诊断”，保存本帧游戏画面、定位框与原始读数，供后续校正。此操作仅写入选择的本地文件夹，不导出接口配置或密钥。

AI 回合教练
默认关闭，每次启动保持关闭。关闭不会影响离线资料与本地规则推荐。
进入“自定义 API 配置”，填写 HTTPS 地址、模型和密钥。兼容 Chat Completions 接口，通常地址以 /v1 结尾。
支持本机 HTTP localhost / 127.0.0.1；外部服务需 HTTPS。可保存多套配置与测试连接。
GPT-6.1 Sol 官方接口：地址 https://api.openai.com/v1，模型 gpt-6.1-sol，密钥填写自己的 OpenAI API Key。
0.1.2 已修正该模型的输出参数；普通分析使用 low 推理，深入分析使用 medium。遇到错误将显示服务返回的具体原因，并隐藏密钥。
密钥使用 Windows DPAPI 按当前用户加密，不能直接搬到其他 Windows 账户解密。
开启后，局面与相关规则发送给所配置的服务商；不上传截图。没有内置付费服务或默认密钥。
自动分析要求：开启实时识别和自动更新，阶段/回合/资金/等级/商店及其费用全部通过稳定检查。自动模式同时要求整组商品对应通过；也可使用手动布局。
默认每回合一次；可选局面变化后更新。调用间隔、每局上限和超时可调整。
请求失败仍可使用本地建议。关闭开关会取消在途请求，也阻止排队请求启动。
AI 返回建议后逐项核验当前已知条件；未通过的操作显示“需人工核对”。局面改变会标记旧建议过期。
不支持的出售或指令操作不会被标为已校验；这类规划仍需人工判断。
0.1.2 已使用 OpenAI 官方 GPT-6.1 Sol 完成真实连接测试及一次人工构造局面的分析，分别约 2.1 秒与 6.7 秒；仅为本机当次结果，不能代表长期延迟或实战策略质量。其他兼容性场景使用本机模拟接口检查。
